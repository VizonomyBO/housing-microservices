# Epic 6: Infrastructure & DevOps

**Context**: Epic 6 owns the Terraform modules, networking, compute, secrets, observability, and CI/CD workflows described in `docs/infrastructure/infrastructure_and_deployment.md`. The reference architecture now uses EC2 Auto Scaling Groups, self-managed Postgres on EC2, ElastiCache Serverless (Valkey), and GitHub Actions pipelines that cover lint/test/build/scan, Terraform apply, blue/green deploys, and migration orchestration.

## Task 6.1 — Networking, Load Balancing & Secrets

**Goal**: Define Terraform modules for the VPC, subnets, security groups, ALB, Route53, TLS certificates, and Secrets Manager wiring.

**What to do**
- Implement the `vpc`, `subnet`, and `security-group` modules matching the three-tier layout (public ALB/NAT, private app, private data) with cross-AZ redundancy.
- Configure an Application Load Balancer terminating TLS (ACM certificate), forwarding to API EC2 target groups, and emitting access logs.
- Provision Route53 records (`api.vizonomy.dev`, etc.) tied to the ALB.
- Create Secrets Manager entries (DB credentials, API keys, rate limiter tokens) and IAM roles/policies so EC2, Lambdas, and Step Functions can fetch them. Capture the user-data/bootstrap scripts that pull secrets into systemd services.
- Document port matrices, CIDR rules, and least-privilege IAM relationships.

**Deliverables**
- Terraform modules + diagrams explaining subnet usage and secret distribution.

## Task 6.2 — Compute & Data Plane (EC2 ASGs, Postgres, Cache, Lambdas)

**Goal**: Provision compute resources per the current design (not Aurora/ECS).

**What to do**
- Define EC2 Auto Scaling Groups for the FastAPI service and the async worker fleet (separate groups for isolation) with target-tracking policies (CPU/memory/QueueDepth) and `systemd` user-data to fetch secrets + containers.
- Provision self-managed Postgres on EC2 via the `postgres-ec2` module: configure storage, backups, replication, pgvector/ltree enablement, and maintenance scripts (snapshots, pg_dump to S3). Document rationale vs. RDS.
- Set up ElastiCache Serverless (Valkey) plus parameter groups for rate limiting + cache telemetry.
- Manage Step Functions and Lambda packaging (container images), ensuring IAM roles allow S3/EventBridge/SQS interactions.
- Provide runbooks for patching AMIs, rolling restarts, and failover.

**Deliverables**
- Terraform definitions + documentation for ASGs, Postgres EC2, cache, and Lambda resources, including health check endpoints and scaling policies.

## Task 6.3 — Observability, Monitoring & Incident Response

**Goal**: Wire CloudWatch metrics/alarms, log shipping, tracing, and on-call runbooks.

**What to do**
- Enable structured logging (FireLens/CloudWatch Logs), metric filters (request latency, job lag, cache hit rate), and alarms for CPU/memory/SQS depth/Postgres replication lag.
- Integrate distributed tracing (X-Ray or OpenTelemetry collector) with LangGraph, API, and workers.
- Define health endpoints (`/health/live`, `/health/ready`) and ALB/ASG integration for automated recovery.
- Document incident response playbooks: scaling runbooks, Postgres failover, cache flushes, rate limiter overrides.

**Deliverables**
- Terraform alarm definitions, dashboard references, and runbook links in the epic.

## Task 6.4 — CI/CD Pipelines (GitHub Actions)

**Goal**: Expand CI/CD to cover lint, tests, scans, image publishing, Terraform apply, blue/green deploys, migrations, and smoke checks.

**What to do**
- CI (`ci.yml`): run `uv sync`, `ruff format --check`, `ruff check`, `ty check`, `pytest -n auto`, `docker build`, and Trivy scans. Publish artifacts (coverage, SBOM) for auditing.
- CD (`deploy.yml` or similar): on merge/tag, build/push Docker images to ECR, run `terraform plan/apply` (with manual approval gates), roll out EC2 ASGs via blue/green or rolling updates, and trigger Step Functions/Lambda deployments.
- Automate DB migrations: run `shared-data-layer migrate` on a maintenance host with retries + alerting, and verify success before shifting traffic.
- Run post-deploy smoke tests (hit `/health/live`, `/v1/chat` dry run, SSE handshake) and roll back automatically if failures occur.
- Capture rate-limit/idempotency keys and secrets via GitHub Actions OIDC + AWS roles.

**Deliverables**
- Updated CI/CD workflow files, documentation of promotion steps (staging→prod), and checklists for approvals/rollbacks.
