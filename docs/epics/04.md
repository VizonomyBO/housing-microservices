# Epic 4: API Gateway & Service Layer

**Context**: Epic 4 covers the FastAPI gateway inside `services/agent-api`, including LangGraph streaming, document attachments, exports, pillar summaries, and middleware defined in `docs/interfaces/api_contracts.md`. The gateway must proxy SSE traffic from LangGraph, enforce shared headers (`Authorization`, `Idempotency-Key`, `Viz-Request-Id`), expose PDF exports, and emit rate-limit + cache telemetry.

**Key Design Docs**
- `docs/interfaces/api_contracts.md` (§§1–4 REST + SSE contracts)
- `docs/security/auth_and_tokens.md` (auth, headers, idempotency)
- `docs/overview/system_architecture.md` §3 (API topology, rate limiter)
- `docs/agents/implementation.md` §5 (SSE envelopes, attachment visibility rules)

## Task 4.1 — Gateway Skeleton, Auth & Cross-cutting Middleware

**Goal**: Stand up FastAPI with the mandated middleware stack.

**What to do**
- Implement JWT validation (aud/iss/sub claims), tenant scoping, and connection to the shared rate limiter dependency.
- Inject `Viz-Request-Id` (generate if absent), enforce `Idempotency-Key` on POST endpoints, and set `RateLimit-*` headers on all responses.
- Provide structured error envelopes per the API contract (`code`, `message`, `request_id`, `details`) and log correlation IDs for tracing.

**Deliverables**
- Middleware unit tests verifying header handling, idempotency storage, and 401/429 responses.
- Documentation describing how downstream services consume `Viz-Request-Id` and how idempotency stores map to `ingestion_jobs`.

## Task 4.2 — `/v1/chat` Streaming & SSE Proxy

**Goal**: Implement the chat endpoint that streams LangGraph output via SSE while relaying telemetry.

**What to do**
- Wrap the LangGraph executor (Epic 3) using LangServe or a custom bridge that emits SSE events exactly as defined (`message.delta`, `task_start`, `task_end`, `cache_event`, `hitl.pause`, etc.).
- Surface cache hits/misses, attachment visibility overrides, and rate-limit usage as inline SSE events and HTTP trailers as defined in the contract.
- Support attachments via `conversation_documents`, validating base-doc auto-attach policy and user-supplied attachments (type, country scope).
- Emit `Viz-Request-Id` as part of SSE metadata and propagate to LangGraph nodes for logging.

**Deliverables**
- API docs + tests covering streaming responses, heartbeat events, retries (Idempotency-Key), and attachment validation.

## Task 4.3 — Document & Attachment APIs

**Goal**: Bring upload, attachment management, and retrieval endpoints in sync with the shared data layer.

**What to do**
- `POST /v1/documents/upload` issues pre-signed URLs and records pending documents/ingestion jobs; enforce dedup semantics and return the `document_id` + `ingestion_job_id`.
- `POST /v1/conversations/{id}/attachments` to add/remove documents, applying guardrails (ownership, country code, visibility override), and auto-attaching base docs for the conversation’s country.
- `GET /v1/conversations/{id}` and `GET /v1/conversations/{id}/messages` hydrate from `shared_data_layer` repositories, including pagination and evidence payloads.

**Deliverables**
- Tests verifying attachment guardrails, base-doc auto-attach, and ref-count updates in `documents.active_chat_refs`.

## Task 4.4 — Export & Pillar Endpoints

**Goal**: Cover the missing export + pillar APIs from `api_contracts.md`.

**What to do**
- `POST /v1/export/pdf` triggers the async export workflow, enforces `Idempotency-Key`, and returns an export id + polling URL.
- `GET /v1/export/{export_id}` (status) surfaces progress, download URLs from `artifacts`, and any user-facing errors.
- `GET /v1/pillars/{country_code}` reads from `pillar_answers` + `pillar_answer_sources`, includes cache headers, and exposes attachment overrides (base docs vs. user docs).

**Deliverables**
- Contract tests for export lifecycle + pillar summaries, ensuring `shared_data_layer` repositories are used for data access.

## Task 4.5 — Observability, Metrics & Rate Limiter Wiring

**Goal**: Provide holistic telemetry for REST + SSE endpoints and ensure every route participates in the shared rate limiter + cache instrumentation.

**What to do**
- Emit structured logs and Prometheus/OTel metrics for latency, token usage, cache hits, SSE duration, export job enqueue latency, and pillar cache age.
- Record `RateLimit-Remaining`, `RateLimit-Reset`, and custom cache headers specified in the contracts.
- Ensure middleware and route handlers share the Valkey connection + limiter instance from Epic 2/3, avoiding duplicate connections.
- Validate attachment/file payloads (size, MIME) before writing to S3 and propagate errors via the standard envelope.

**Deliverables**
- Dashboard-ready metric names documented in the epic, plus automated tests for rate-limit headers and cache telemetry events.
