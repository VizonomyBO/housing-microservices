# Epic 5: Async Workers

**Context**: A separate service (`services/agent-worker`) that consumes SQS queues for heavy lifting.

**Key Design Docs**:
- `docs/infrastructure/async_jobs.md` (Job Types)
- `docs/overview/images/pdf_export_pipeline.png`

## Task 5.1 — Worker Skeleton & SQS Consumer

**Goal**: A robust loop to process messages.

**Reference**: `infrastructure/infrastructure_and_deployment.md` 3.2.

**Implementation**:
- Python script that polls SQS.
- Dispatcher logic based on `message_attributes.type`.
- Error handling: Dead Letter Queue (DLQ) logic.

**Deliverables**: Service that logs "Received message X" from SQS.

## Task 5.2 — PDF Export Worker

**Goal**: Generate Reports.

**Reference**: `async_jobs.md` (PDF Export).

**Implementation**:
- Fetch conversation history via `shared_data_layer`.
- Render Jinja2 HTML template.
- Use WeasyPrint or Headless Chrome to generate PDF.
- Upload to S3 `reports/`.

**Deliverables**: SQS message triggers creation of a PDF in S3.

## Task 5.3 — Pillar Answer Worker

**Goal**: Batch RAG processing.

**Reference**: `overview/images/pillar_answer_jobs.png`.

**Implementation**:
- Re-use the `RetrievalOrchestrator` from Epic 3 (import logic, don't duplicate).
- Run RAG chain for specific questions.
- Persist results to `pillar_answers` table.

**Deliverables**: Rows appearing in `pillar_answers` after doc upload.
