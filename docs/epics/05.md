# Epic 5: Async Workers & Queue Orchestration

> **Archived (pre-revamp):** This epic references the deprecated async worker/SQS/Step Functions + cache stack. The current platform is synchronous ingestion-first with no worker fleet or cache/rate-limiter layer. Use the docs under `docs/overview` and `docs/agents` for the supported architecture.

**Context**: Epic 5 covers the asynchronous workloads that offload long-running or multi-stage jobs from the API. The worker fleet (part of `services/agent-worker`) consumes SQS queues described in `docs/infrastructure/async_jobs.md`, enforces LangGraph checkpoint semantics for HITL pauses, and keeps caches, exports, and ingestion jobs in sync with `shared_data_layer`.

- `docs/overview/system_architecture.md` §4 (async topology, EventBridge notifications)

## Task 5.1 — Worker Runtime, Dispatch & Checkpoint Integration

**Goal**: Build the worker runtime that polls SQS queues (ingestion, export, pillar, maintenance), dispatches to job-specific handlers, and wires LangGraph checkpointing for interruptible work.

**What to do**
- Implement a resilient polling loop (batched receives, visibility extensions, heartbeat metrics) with message dispatch keyed off `message_attributes.type`.
- Share Valkey rate limiter + secrets loader with Lambdas, and load `shared_data_layer` repositories for DB access.
- Integrate LangGraph checkpoint support: ingestion/HITL workers must persist state, emit `interrupt` when awaiting user input, and resume when API receives a callback (thread id = `job_id`).
- Enforce idempotency tokens/job dedup IDs from the payload; skip or cancel work if `document.status` no longer requires it.

**Deliverables**
- Worker bootstrap module, retry/backoff utilities, and integration tests using mocked SQS + Postgres checkpoints.

## Task 5.2 — Ingestion Queue Consumers (Validation, Chunking, Embedding)

**Goal**: Process `ingest_document` jobs end-to-end, mirroring the Step Functions stages but running inside the worker fleet for replays or manual ingestion (per `async_jobs.md`).

**What to do**
- Validate payloads (document existence, hash, ownership) before work; update `ingestion_jobs` status/attempt counters and emit EventBridge progress events.
- Orchestrate table normalization, chunk building, embedding writes, graph extraction, cache invalidation, and maintenance refresh triggers when chunks/graph rows change.
- Audit every stage (`job_events` table or equivalent) and write structured errors to `ingestion_jobs.last_error` plus the DLQ message body when retries exhaust.
- Invalidate relevant cache keys (Valkey) and refresh materialized views when new embeddings/graph edges land.

**Deliverables**
- Handler modules for each ingestion stage with unit tests verifying status updates, cache invalidation, and view refreshes.

## Task 5.3 — PDF Export Worker

**Goal**: Implement the `export_pdf` job pipeline so async workers generate artifacts, update status APIs, and respect attachment visibility rules.

**What to do**
- Fetch conversation history, citations, and document attachments through repositories with visibility overrides intact.
- Render HTML via templates, generate PDFs (WeasyPrint/Chromium), upload to S3 under `reports/{conversation_id}/{job_id}.pdf`, and write an `artifacts` row + export status (per API contracts).
- Publish completion/failure events to EventBridge so `/v1/export/{id}` polls stay accurate and SSE notifications can fire.
- Enforce cache invalidation for any derived summaries and ensure DLQ/error payloads include `conversation_id`, `export_id`, and `request_id`.

**Deliverables**
- Export worker implementation + tests covering successful generation, attachment guardrails, and DLQ writes.

## Task 5.4 — Pillar Answer & Async Insight Workers

**Goal**: Run offline RAG jobs (pillar answers, retrieval telemetry replays) that populate `pillar_answers`, `pillar_answer_sources`, and `retrieval_run_items`.

**What to do**
- Reuse Epic 3 RetrievalOrchestrator nodes rather than duplicating logic; run within LangGraph where appropriate so checkpoints capture intermediate context.
- Batch questions per country or regulatory pillar, enforce rate limits, and cache results keyed by `(pillar, country_code, document_hashes)`.
- Write results to the shared data layer tables and emit cache refresh events so `/v1/pillars/{country_code}` serves the latest data.
- Support callback semantics: when a job finishes, POST to `/internal/jobs/{id}/complete` (or publish EventBridge event) so the API can notify clients.

**Deliverables**
- Worker handlers + regression tests verifying DB writes, caching, and callback invocation.

## Task 5.5 — DLQ Handling, Monitoring & Runbooks

**Goal**: Provide observability, retry/DLQ policies, and operational tooling required by `async_jobs.md`.

**What to do**
- Configure per-queue metrics (`queue_depth`, `job_latency`, `error_rate`), alerts (high DLQ volume, processing lag), and dashboards.
- Implement DLQ replay tooling (CLI command + runbook) that re-enqueues sanitized payloads after human review.
- Document payload auditing requirements (store hashed payloads for 30 days, redact secrets) and cache invalidation hooks when replaying jobs.
- Ensure workers expose `/health/ready` and `/metrics` endpoints for ASG target groups.

**Deliverables**
- Monitoring configuration references, DLQ replay script, and documentation linking runbooks to the design docs.
