# Epic 3.5: Reduced Scope MVP Adaptation

**Context**: Management needs a demo-ready build tomorrow, so we must run the platform in a “text-only, no-Valkey” safe mode while preserving all advanced architecture for quick reactivation. This epic replaces the remaining scopes from Epics 4–7 by constraining every service to consume only plain-text chunks emitted by the markitdown-based ingestion owned by another teammate. Image/table ingestion, image captions, and Valkey-backed rate limiting/caching stay in the tree but are gated off through feature flags, short-circuit branches, or explicit TODO markers instead of code deletion.

**Key Design Docs**
- `docs/overview/system_architecture.md` §§2–3 (LangGraph topology, limiter/caching expectations)
- `docs/data/schema_and_persistence.md` §3 (documents/chunks tables used for text-only retrieval)
- `docs/interfaces/api_contracts.md` §§1–4 (REST/SSE contracts that still govern the MVP)
- `docs/infrastructure/infrastructure_and_deployment.md` §3 (EC2/Postgres layout to slim down)
- `docs/security/auth_and_tokens.md` §2 (header, auth, and verification rules to keep intact)

> _Note_: Ingestion scope is intentionally omitted—markitdown text extraction is supplied externally, and this epic only adapts downstream consumers.

## Task 3.5.1 — Gateway Safe Mode & Text-only Streaming (Replaces Epic 4.1, 4.2, 4.5)

**Goal**: Run `services/agent-api` without Valkey or non-text retrieval while preserving the LangGraph gateway contracts.

**What to do**
- Add `ReducedScopeSettings` (e.g., `settings.reduced_scope.enabled`, `text_only_chunks`, `disable_valkey`) so middleware, dependency providers, and LangGraph runners can branch without deleting Valkey/rate-limiter code (`docs/epics/04.md:11-36`, `docs/overview/system_architecture.md:642-717`).
- Replace the Valkey/RateLimiter singletons with no-op shims when reduced scope is on: emit headers with static “unavailable for demo” metadata, skip quota enforcement, and ensure SSE telemetry simply reports `"rate_limit_disabled": true`.
- Constrain `/v1/chat` and LangGraph state hydration to `chunk_type='text'` (`docs/data/schema_and_persistence.md:172-205`): filter Vision/Numerical/table branches at the router level, and short-circuit any node that would call the removed channels with a “feature temporarily disabled” event.
- Keep SSE wiring intact but drop image/table-specific payloads by adding guards around `CacheWriter`, `VisionTool`, and attachment visibility emitters. Emit a single “demo-mode skipped” SSE event so the client transcript stays coherent.
- Document the flag semantics inside `docs/agents/implementation.md` and `docs/interfaces/api_contracts.md` so future re-enablement only requires flipping the settings.

**Deliverables**
- Updated FastAPI config + dependency graph, LangGraph runner guards, SSE contract notes, and regression tests that prove `/v1/chat` succeeds without Valkey.

## Task 3.5.2 — Text-only Document, Attachment & Pillar APIs (Replaces Epic 4.3 & 4.4 surfaces)

**Goal**: Keep document/attachment/export endpoints responsive while limiting them to text chunks and synchronous flows.

**What to do**
- Gate `POST /v1/documents/upload` and `/v1/conversations/{id}/attachments` so they accept only markitdown text payloads: reject `chunk_type in ('table','image')` with 202 responses that point to the disabled feature, and auto-complete `ingestion_jobs` records to `succeeded` using a helper instead of invoking the normal ingestion queue.
- Preserve base-document auto-attach logic (`docs/data/schema_and_persistence.md:90-155`) but wrap the enrichment of attachment metadata (figures, tables) in `if not settings.reduced_scope.text_only`. When disabled, store the metadata stub (`{"status":"skipped"}`) so audit history remains.
- Drop the PDF export requirement entirely for the MVP—clients will render any printable view themselves. Instead, expose a synchronous `GET /v1/pillars/{country_code}` (and optional `/v1/conversations/{id}/pillars`) endpoint that returns JSON pillar answers derived from Text-to-SQL aggregations over the text chunks, including citations and metadata for the frontend to format. Clearly mark the deferred PDF/export flow with TODO comments for post-demo reactivation.
- Update API docs/test fixtures so clients understand that attachments, exports, and pillar calls only surface text content during the demo build.

**Deliverables**
- Modified handlers, repositories, and tests demonstrating text-only uploads/attachments, JSON pillar responses, and updated contract documentation.

## Task 3.5.3 — Synchronous Job Execution (Replaces Epic 5.x)

**Goal**: Remove the need for SQS/SFN workers entirely for the MVP by executing any remaining long-running work inline (API request or CLI) while leaving the full worker/runtime code available for later.

**What to do**
- Introduce a `ReducedScopeWorkerRuntime` (or helper module) that exposes pure-python functions for ingestion-complete bookkeeping, pillar generation, and artifact creation. When the reduced-scope flag is on, surface these helpers via FastAPI routes/CLI commands rather than launching separate worker processes.
- Remove any reliance on queues (SQS/EventBridge) for the MVP by commenting or flagging out the polling loops; calls that previously enqueued jobs should now `await` the synchronous helper directly and return the result to the client.
- Ensure the synchronous helpers reuse the repositories/Text-to-SQL utilities from Task 3.5.2 so writes still flow through `pillar_answers`, `pillar_answer_sources`, `artifacts`, and `ingestion_jobs`, albeit without Valkey cache invalidation.
- Provide operational docs/scripts describing how to re-enable the queue workers after the demo (e.g., uncomment `agent-worker` entry points, restore SQS configuration, re-enable async exports).
- Update tests to cover the synchronous execution path while keeping the original worker tests skipped/flagged until queues return.

**Deliverables**
- Synchronous helper modules, updated API/CLI integration, and documentation describing how to re-enable full SQS/Valkey execution later.

## Task 3.5.4 — Local Deployment via Docker Compose (Replaces Epic 6.x + CI/CD scope)

**Goal**: Deliver a manual deployment story focused on Docker Compose and local containers, deferring GitHub Actions CI/CD and non-essential AWS resources until after the demo.

**What to do**
- Author a dedicated Dockerfile for `services/agent-api` that installs the service plus the shared data layer package, seeds markitdown text fixtures, and wires settings for reduced scope.
- Create a Docker Compose file/profile (`docker-compose.reduced.yml` or `docker-compose.yml` with profiles) that brings up FastAPI, Postgres (with pgvector), and any auxiliary services still required (e.g., vector DB), omitting Valkey, SES, and worker containers. Document manual startup + teardown steps for the demo.
- Update `docs/infrastructure/infrastructure_and_deployment.md` to reflect the manual deployment path and clearly state that GitHub Actions CI/CD, Terraform-managed Valkey/SES, and ASGs are paused until the flag flips back.
- Provide guidance for connecting local services (API ↔ Postgres) plus sample `.env` entries so teammates can run the entire reduced-scope stack with `docker compose up`.
- Keep the prior CI/CD automation notes in comments or follow-up sections so reintroducing GitHub Actions + Terraform after the demo only requires reverting the documented changes.

**Deliverables**
- Dockerfile + Compose profile, updated infrastructure docs, and a manual runbook for standing up/tearing down the reduced-scope stack.

## Task 3.5.5 — Auth & Notification Fallback (Replaces Epic 7.x)

**Goal**: Keep registration/password flows usable without SES or Valkey-backed abuse controls while preserving the future-ready email architecture.

**What to do**
- Guard the SES Terraform/resources (`docs/epics/07.md:12-160`) and `services/auth-service` email service initialization behind `settings.reduced_scope`. When enabled, route email calls to a `LoggingEmailProvider` that writes the payload to structured logs and immediately marks verification tokens as delivered so onboarding is unblocked.
- Replace Valkey-dependent rate-limiting (Epic 7.7) with lightweight, per-process counters that enforce only the minimum IP limits required by security (`/forgot-password` 3/hr, `/verify-email` 10/hr) and add TODO comments showing where the Valkey adapters plug back in.
- Provide an admin-only CLI endpoint (or FastAPI route under `/internal`) that can manually flip `email_verified` for demo accounts, ensuring the UI flow works without waiting for real emails.
- Keep all SES templates/config structures in code but disable their application in migrations/deployments; annotate the epic + README so teammates know those sections are frozen until Valkey/SES are re-enabled.

**Deliverables**
- Reduced-scope email provider, config flags, updated auth endpoints/tests, and documentation describing how to restore the full SES + Valkey-backed abuse prevention after the demo.

---

Completing Epic 3.5 yields a demonstrable system that streams LangGraph answers from markitdown text chunks, surfaces text-only document operations, performs synchronous exports/pillars, deploys with only FastAPI + Postgres, and keeps auth flows moving—all without deleting the advanced image/table/rate-limit code that will be re-enabled post-demo.
