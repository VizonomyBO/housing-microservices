# Epic 2: Document Ingestion Pipeline

**Context**: Epic 2 covers the Step Functions workflow and Lambda/LangChain utilities that turn uploaded binaries into normalized tables, vectors, graph entities, and audit records described in `docs/interfaces/api_contracts.md` §2 and `docs/overview/system_architecture.md` §2.1. Every stage must emit progress via EventBridge, update `ingestion_jobs`, and use the shared rate limiter, metrics, and secrets helpers.

**Key Design Docs**
- `docs/interfaces/api_contracts.md` §2 (ingestion API + state machine contracts)
- `docs/overview/system_architecture.md` §2.1 (ingestion topology)
- `docs/data/schema_and_persistence.md` §§3.2–3.5 (documents, chunks, telemetry)
- `docs/data/knowledge_graph.md` (graph extraction + workflow refresh)

## Task 2.1 — Step Function Definition, Preflight, and Progress Events

**Goal**: Define the ASL state machine and implement the `preflight-validator` Lambda that performs deduplication, idempotency enforcement, and `ingestion_jobs` bookkeeping.

**What to do**
- Model every stage described in `api_contracts.md` (preflight → convert → normalize tables → caption images → chunk → embed → index → activate + graph refresh). Include choice/failure branches, DLQ handling, and EventBridge progress events.
- `preflight-validator` responsibilities: MIME sniffing, SHA-256 hash calculation, `documents` lookup via `shared_data_layer`, skip/attach behavior for duplicates, idempotency token persistence, and optimistic `ingestion_jobs` rows (`status=running`, `attempt+=1`).
- Emit `vizonomy.ingestion.progress` events at start/finish/failure of each state with the schema defined in the contracts doc.

**Deliverables**
- Checked-in ASL definition with unit tests.
- Lambda that returns the canonical `ingestion_job_id`, writes audit fields, and seeds Step Functions context for downstream Lambdas.

## Task 2.2 — Conversion, Table Normalization & Artifact Writes

**Goal**: Produce Markdown, table JSON, and raw assets exactly as defined in §2.3 of the API contracts.

**What to do**
- `marker-converter` (or equivalent) writes Markdown, page-metadata JSON, and raw figures to S3 while updating the `artifacts` table via `shared_data_layer`.
- `table-normalizer` Lambda ingests table JSONL emitted by the converter, normalizes header/body cells, and stores them back in S3 under `/tables/`. It also generates schema summaries used later by the retrieval service.
- Update `documents.ingestion_stage` + `ingestion_jobs` for each successful completion and emit progress events.

**Deliverables**
- S3 directory structure documented in the epic (e.g., `/raw`, `/markdown`, `/tables`, `/figures`).
- Regression tests that verify `artifacts` rows + `documents` timestamps are set.

## Task 2.3 — Chunking, Image Captioning & Embeddings

**Goal**: Produce text/table/image chunks with captions and embeddings before committing to Postgres.

**What to do**
- `chunk-builder` Lambda reads normalized Markdown/table payloads, enforces 800-token chunk windows, and emits chunk manifests to S3 (`/chunks/{document_id}.jsonl`).
- `image-captioner` Lambda converts figure assets into captions/bboxes and appends them to the chunk manifest for ingestion to `chunks`.
- `embedding-writer` Lambda batch-fetches the manifest, calls Voyage 3.5-lite through the shared rate limiter, and persists `chunks` + `chunk_metrics` through repository helpers.
- Enforce retry/idempotency semantics and update `ingestion_jobs` for `chunk`, `caption`, `embed`, and `index` stages.

**Deliverables**
- Documentation of manifest schemas and how they map onto the `chunks` columns (`chunk_type`, `table_payload`, `image_caption`, `embedding`).
- Integration tests proving chunk + metrics rows appear and `active_chunks` refresh hooks fire.

## Task 2.4 — Graph Extraction, Community Refresh & Evidence Rollups

**Goal**: Make graph extraction mandatory and keep graph-related materializations in sync.

**What to do**
- `graph-extractor` Lambda reads the same chunk manifest, prompts the LLM for entities/edges/evidence, and writes them to `graph_entities`, `graph_edges`, `graph_evidence`.
- Trigger maintenance helpers to refresh `graph_edge_evidence_rollup`, `graph_hot_entities`, and workflow graph differencing once ingestion hits the `activate` state.
- Ensure graph + workflow refresh failures feed back into `ingestion_jobs` and propagate failure events so operators can replay.

**Deliverables**
- Tasks and acceptance criteria for the extractor Lambda, maintenance hook wiring, and regression tests around graph rollups/community refreshes.

## Task 2.5 — Shared Tooling, Rate Limiter & Auditing

**Goal**: Guarantee every Lambda consumes the shared SDKs (rate limiter, secrets, metrics, tracing) and records auditable history.

**What to do**
- Adopt the centralized Valkey-based rate limiter and emit `RateLimit-Remaining` style metrics per stage.
- Use the shared secrets loader for API keys and the metrics emitter for durations, token counts, `ivfflat.probes` overrides, etc.
- Persist structured `ingestion_jobs.last_error`, worker identifiers, and `document_gc_events` hooks when ingestion fails.
- Capture audit trails for dedup, table normalization, captioning, and graph extraction outputs in S3 + Postgres.

**Deliverables**
- Documentation + code stubs showing the common utilities wired into every Lambda.
- Runbooks for retry/idempotency, EventBridge notifications, and DLQ replays tied back to `docs/infrastructure/async_jobs.md`.
